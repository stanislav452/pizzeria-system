# Лабораторна робота №7–9

## Типізований CRUD-сервіс

Предметна область — електронне меню піцерії. У програмі є сутності `Pizza` (назва, ціна, діаметр) і `Order` (назва, кількість піц, додатковий соус).

## Реалізація

- `BaseEntity` містить незмінні `id` і `name`. `equals()` та `hashCode()` працюють за `id`.
- `EntityNotFoundException` є неперевіреним винятком (`RuntimeException`): відсутній запис можна обробити там, де це потрібно, без обов'язкового оголошення винятку в кожному методі.
- `CRUDService<T extends BaseEntity>` обмежує тип сутностями з `id` і `name`. Завдяки цьому загальний сервіс може працювати з ідентифікаторами та сортувати за назвою.
- `InMemoryCrudService<T>` зберігає записи в `LinkedHashMap`. Метод `save` додає запис або замінює запис з таким самим `id`.
- Сортування виконується через `Comparator`, оскільки для різних сутностей та задач потрібні різні правила. Сортування повертає новий список і не змінює сховище.
- `PizzaService` та `OrderService` містять сортування за назвою та відповідним полем сутності. Цей метод не входить до загального CRUD-контракту, бо кожна сутність має власні поля.
- `findAllSorted` приймає `Comparator<? super T>`, щоб можна було передати компаратор для `T` або його батьківського типу.
- `printAll(Collection<? extends BaseEntity>)` приймає колекції сутностей-нащадків. `List<Pizza>` не є `List<BaseEntity>`, але підходить для колекції з wildcard `? extends BaseEntity`.

Компаратор сортує за назвою та додатковим полем, а `equals` визначає рівність тільки за `id`. Тому результати компаратора не обов'язково узгоджені з `equals`; це нормально для сортування списку. Не слід використовувати такий компаратор як єдиний критерій у `TreeSet` або `TreeMap`, де порівняння може визначати унікальність елементів.

## Вибір колекції

`LinkedHashMap<Long, T>` обрана для швидкого пошуку за `id` і збереження порядку додавання. Наведені складності — середні для хеш-колекцій.

| Колекція | `findById` | `save` | `delete` | Відсортований список |
|---|---:|---:|---:|---:|
| `ArrayList` | O(n) | O(1) в кінець, O(n) для оновлення/пошуку | O(n) | O(n log n) |
| `HashMap` | O(1) | O(1) | O(1) | O(n log n) для копії та сортування |
| `LinkedHashMap` | O(1) | O(1) | O(1) | O(n log n) для копії та сортування |
| `TreeMap` | O(log n) | O(log n) | O(log n) | O(n) для обходу за ключем; для інших полів потрібне окреме сортування |

## Запуск

Потрібен JDK. У корені проєкту виконайте:

```bash
javac *.java
java Main
```

`Main` показує додавання, оновлення без збільшення кількості записів, пошук, успішне та неуспішне видалення, обробку відсутнього `id` і сортування для обох сутностей.
